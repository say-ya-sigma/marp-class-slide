# アーキテクチャと<br>データベース
<!-- _class: lead -->

# ソフトウエアのアーキテクチャとは
* システムの基本的な構造を定義する概念
* システムの構成要素とその相互関係を示す

# アーキテクチャのデータベースへの<br>影響
* アプリケーションのアーキテクチャのデータベースへの影響
  * データベースの選定
  * データベースの設計
  * データベースの運用

# データベースができるとは
* データベースができるの意味合いも多様になってきている
  * SQLが書ける
  * ORMが使いこなせる
  * マイグレーションファイルの運用ができる
  * データベースの設計ができる
  * データベースのパフォーマンスチューニングができる
* バックエンドへの理解が必要不可欠になりつつある


# 視野を広げよう
* 視野を広げてアプリケーションの中でデータベースがどう扱われているか感覚をつかもう
* そのためにメジャーなアーキテクチャに触れて行きます

# オブジェクト指向的な資産にも触れる
* 「こういう道具にはこういう機能がありそうだな」という開発者間における共通認識を持てる道具を作ってきた
* GoF本とかPoEAA本などでカタログ化されている
